# 매크로 공방 (MacroKit) — 개발 문서

> 상태: 1~5단계 구현 완료, 게임 안 확인 전 · 작성 2026-11-10
> 대상 클라이언트: WoW 포에버 1.60.x (Interface 16001)

## 1. 한 줄 요약

**게임 안에서** 와우풍 창을 열어 매크로 템플릿을 고르고, 빈칸(주문·대상 등)만 채운 뒤 **[등록]** 을 누르면 매크로가 만들어지는 애드온.
매크로 문법(`/cast [@mouseover,harm,nodead] ...`)을 몰라도 쓸 수 있게 하는 것이 목표다.

## 2. 사용자 흐름

```
/매공 (또는 단축키)   ※ /매크로 는 게임 기본 명령(매크로 창)과 겹칠 수 있어 쓰지 않는다
  ▼
[매크로 공방] 창
  ├ 왼쪽: 직업 탭 (내 직업이 먼저 선택됨) → 분류(공격/차단/치유/소환수/유틸) → 템플릿 목록
  └ 오른쪽: 선택한 템플릿
       설명 한두 줄 ("마우스를 올린 적에게 바로 시전, 없으면 내 대상에게")
       빈칸:  주문 [ 공포 ▼ ]   대상 [ 마우스오버 → 대상 ▼ ]
       미리보기: 실제 매크로 본문 (글자 수 / 255)
       이름 [ 공포-마우스 ]   아이콘 [자동]   ( ) 공용  (•) 캐릭터 전용
       [등록]  → 완료되면 아이콘이 창에 나타남 → 끌어서 행동 단축바에 놓기
```

- 이미 이 애드온으로 만든 매크로를 같은 템플릿으로 다시 등록하면 **덮어쓰기** 할지 묻는다 (새로 만들지 않음).
- 아래 띠에 남은 칸 표시: `공용 37/120 · 캐릭터 5/18`.
- [내 매크로] 탭: 이 애드온이 만든 매크로 목록 → 다시 편집 / 삭제 / 단축바로 끌기.

## 3. 블리자드 제약과 대응

| 제약 | 대응 |
|---|---|
| 전투 중에는 매크로 생성·수정·삭제 불가 (`CreateMacro`/`EditMacro`/`DeleteMacro` 금지) | 전투 중엔 [등록] 비활성 + "전투가 끝나면 등록하세요" 안내. `PLAYER_REGEN_ENABLED` 에 다시 활성 |
| 행동 단축바에 자동으로 올리기 불가 (`PlaceAction` 보호) | 등록 후 창에 아이콘 버튼을 띄우고 **끌어서** 놓게 함 (`PickupMacro` 는 클릭/끌기 이벤트에서 허용) |
| 개수: 공용 120, 캐릭터 18 (클라이언트 값은 `MAX_ACCOUNT_MACROS`/`MAX_CHARACTER_MACROS` 로 읽음) | 남은 칸 표시, 꽉 차면 등록 버튼 대신 안내 |
| 본문 255자 | 미리보기에 글자 수, 넘으면 빨간색 + 등록 막기 |
| 이름 16자 (확인 필요) | 기본 이름을 짧게 만들고 입력 칸 길이 제한 |
| 주문 이름은 클라이언트 언어(한글)로 써야 함 | 템플릿은 **주문 번호(spellID)** 로 저장, 실행 시 `GetSpellInfo(id)` 로 한글 이름을 받아 넣음 → 오타 없음 |
| 주문 등급 | 등급을 쓰지 않으면 가장 높은 등급이 나가므로 기본은 등급 생략. 낮은 등급 템플릿(예: 치유 등급 조절)은 2차 이후 |

## 4. 화면 설계 (게임 안)

- 블리자드 기본 템플릿(`BasicFrameTemplateWithInset`, `UIPanelButtonTemplate`, `UIDropDownMenu`)만 쓴다 → 게임 UI와 자연스럽게 어울림, 외부 그림 파일 없음.
- 크기 약 720 x 460, 드래그 이동, ESC 닫기, 위치 저장 (`MacroKitDB.point`).
- 왼쪽 220px: 직업 탭(공통 + 9개 직업, 아이콘 = 직업 아이콘, 내 직업 먼저) + 분류 머리글 + 스크롤 목록.
  - 내가 배우지 않은 주문만 쓰는 템플릿은 흐리게 표시하고 "아직 배우지 않음" 툴팁 (`IsSpellKnown`/`IsPlayerSpell`).
- 오른쪽: 설명 → 빈칸들 → 미리보기(읽기 전용 여러 줄 상자) → 이름/아이콘/공용·캐릭터 → [등록].
- 빈칸 종류 (`item` 은 9.0 참고)
  - `spell`: 그 템플릿이 허용한 주문 목록 드롭다운 (배운 것만, 아이콘 포함)
  - `target`: 대상 규칙 드롭다운 (5장 참고)
  - `choice`: 템플릿별 선택지 (예: 장신구 위 칸/아래 칸)
  - `check`: 켜고 끄는 옵션 (예: "시전 중이면 끊고 시전 (/stopcasting)")
- 처음 열면 한 번만 안내 말풍선: "템플릿 고르기 → 빈칸 채우기 → 등록 → 아이콘을 단축바로 끌기".

## 5. 대상 규칙 (모든 템플릿 공통)

| 선택지 | 생성되는 조건 (적대 주문 기준) | 설명 |
|---|---|---|
| 내 대상 | (조건 없음) | 일반 시전과 같음 |
| 마우스오버 → 대상 | `[@mouseover,harm,nodead][]` | 마우스를 올린 적, 없으면 내 대상 |
| 주시 → 대상 | `[@focus,harm,nodead][]` | 주시 대상, 없으면 내 대상 (**클래식 계열 클라이언트에서 주시 지원 여부 확인 필요**) |
| 마우스오버 → 주시 → 대상 | `[@mouseover,harm,nodead][@focus,harm,nodead][]` | |
| 자신 (이로운 주문) | `[@player]` | |
| 마우스오버 → 대상 → 자신 (이로운 주문) | `[@mouseover,help,nodead][help,nodead][@player]` | 치유용 기본값 |

- 주문이 이로운지/해로운지는 템플릿 데이터의 `help = true` 로 구분한다 (`harm` ↔ `help` 자동 치환).
- 클라이언트가 `@` 표기를 모르면 `target=` 표기로 바꾼다 (확인 단계에서 결정, 6장).

## 6. 먼저 확인할 것 (게임 안 진단)

애드온 자체의 `/매공 검사` 가 아래를 한 창에서 보여 준다 (DNProbe 를 따로 깔 필요 없음).
문법 표기(`@` / `target=`)와 주시 지원은 **접속할 때마다 자동으로 검사**해서 맞는 쪽으로 만든다.

1. `CreateMacro`, `EditMacro`, `GetNumMacros`, `PickupMacro` 존재 여부, 최대 개수 값
2. 매크로 조건 지원: `@mouseover` / `target=mouseover`, `@focus`, `nodead`, `harm/help`, `mod:shift`, `/castsequence`, `/stopcasting`, `#showtooltip`, `/startattack`, `/petattack`, `/cancelform`
   - 실제 판정은 `SecureCmdOptionParse("[@player] 예; 아니오")` 의 반환값으로 한다 (매크로를 만들지 않고 검사 가능).
3. `GetSpellInfo(spellID)` 가 한글 이름을 주는지, `IsSpellKnown` 동작
4. 매크로 이름 최대 길이

## 7. 템플릿 데이터 형식

`addons/MacroKit/Templates/<직업>.lua` — 직업별 파일. 사람이 직접 쓰는 데이터.

```lua
local _, ns = ...
ns.AddTemplates("WARLOCK", {
  {
    id = "wl.fear.mouseover",            -- 고유 ID (내 매크로 추적, 덮어쓰기 판단)
    cat = "control",                     -- attack | control | interrupt | heal | pet | utility
    title = "공포 (마우스오버)",
    desc = "마우스를 올린 적에게 공포. 없으면 내 대상에게.",
    name = "공포-마우스",                 -- 기본 매크로 이름 (16자 이내)
    params = {
      { key = "spell",  type = "spell",  label = "주문",  spells = { 5782, 5484 } },   -- 공포, 공포의 울부짖음
      { key = "target", type = "target", label = "대상",  default = "mouseover" },
      { key = "stop",   type = "check",  label = "시전 중이면 끊고 시전", default = false },
    },
    body = {
      "#showtooltip",
      "{stop?/stopcasting}",
      "/cast {target}{spell}",
    },
  },
})
```

- 본문 자리표시자: `{spell}` = 한글 주문 이름, `{target}` = 5장의 조건, `{key?텍스트}` = check 가 켜졌을 때만 그 줄을 넣음, 빈 줄은 지운다.
- 명령어는 **영어 표기(`/cast`, `/use`)로 생성**한다. 한글 클라이언트도 영어 명령을 받고, 한글 명령 지원은 확인되지 않았기 때문. (미리보기에는 "시전" 등 한글 설명을 옆에 붙임)
- 아이콘: 기본은 `#showtooltip` + 물음표 아이콘(134400) → 게임이 주문 아이콘으로 자동 표시.

## 8. 매크로 만들기 로직

```
등록 클릭
  if InCombatLockdown() → 안내 후 중단
  본문 = 템플릿.body 에 빈칸 값 대입 → 255자 검사
  기존 = MacroKitDB.owned[템플릿 id .. 공용/캐릭터]  (매크로 이름 저장)
  if 기존 이름의 매크로가 아직 있음(GetMacroIndexByName) → 덮어쓰기 확인 → EditMacro
  elseif 같은 이름의 남의 매크로가 있음 → 이름 바꾸라고 안내 (남의 매크로는 건드리지 않음)
  else → 칸 남았는지 확인 → CreateMacro(이름, 아이콘, 본문, 캐릭터전용)
  MacroKitDB.owned 갱신 → 창에 끌 수 있는 아이콘 표시 + 채팅 한 줄 결과
```

- 이 애드온은 **자기가 만든 매크로만** 고치거나 지운다. 사용자가 직접 만든 매크로는 절대 건드리지 않는다.
- 저장 데이터: `MacroKitDB` (공용: 창 위치, 첫 안내 여부) + `MacroKitCharDB` (캐릭터 전용 매크로 추적).

## 9. 템플릿 목록 (9개 직업 + 공통)

- 직업 탭은 9개 직업 모두 둔다. 창을 열면 **내 직업 탭이 먼저** 선택되고, 맨 앞에 **공통** 탭이 있다.
- 구현 순서: 공통 → 흑마법사 → 주술사 → 드루이드 → 나머지 6개 직업 (13장).
- 주문 번호는 1등급 기준이다. **번호는 `check_spells.py` 로 게임 데이터와 대조해 199개 모두 확인했다.** 아래 표의 한글 이름은 설계 때 기억으로 쓴 것이라 실제 이름과 다를 수 있다 (예: 980 = 고통의 파멸, 72 = 방패 가격, 6770 = 기절시키기). 실제 이름은 `docs/MacroKit-spells.txt` 가 기준이고, 게임 안에서는 항상 게임이 주는 이름을 쓴다.
- 표기: "마우스오버/주시" = 5장의 대상 규칙 중 고를 수 있다는 뜻. 기본값은 템플릿마다 정한다.

### 9.0 공통 (모든 직업)

| 분류 | 템플릿 | 내용 | 빈칸 |
|---|---|---|---|
| 전투 | 공격 시작 + 기술 | `/startattack` + 주문 | 주문 |
| 전투 | 시전 끊고 시전 | `/stopcasting` + 주문 | 주문 |
| 아이템 | 장신구 + 주문 | `/use 13` 또는 `/use 14` + 주문 | 장신구 칸(위/아래/둘 다), 주문 |
| 아이템 | 물약/생명석 한 버튼 | `/use 생명석` → 없으면 `/use 물약` (같은 버튼 순서대로) | 아이템 목록에서 고르기 |
| 아이템 | 음식·음료 한 버튼 | `/use [mod:shift] 음료; 음식` | 아이템 |
| 이동 | 탈것 | `/use [nomounted] 탈것` + `/dismount [mounted]` | 탈것 아이템 |
| 대상 | 가장 가까운 적 + 공격 | `/targetenemy [noharm][dead]` + `/startattack` | — |
| 대상 | 주시 지정/해제 | `/focus [@mouseover,exists][]` / `/clearfocus` | (주시 지원 시에만) |
| 기타 | 공격대 표시 | `/tm [mod:shift] 0; 8` (해골 표시) | 표시 종류 |

- **아이템 빈칸(`item`)**: 가방과 장비 칸에 있는 아이템 중에서 고른다 (`GetContainerItemID` → `GetItemInfo`). 이름은 게임이 주는 한글 이름을 그대로 쓴다.

## 10. 데이터 검증 도구

`tools/casc/check_spells.py` (새로 만듦)

- 클라이언트 `SpellName.db2` (koKR) 를 casc.py 로 읽어 템플릿 Lua 파일의 모든 spellID 를 찾고, 한글 이름을 옆에 출력한다.
- 없는 번호가 있으면 실패로 끝낸다 → **GitHub Actions 빌드에서는 게임 파일이 없으므로 로컬에서만** 실행. 결과를 `docs/MacroKit-spells.txt` 로 저장해 리뷰에 쓴다 (애드온 폴더에 넣지 않음).
- SpellName.db2 는 일부 구역이 암호화(미공개 데이터)되어 있다. 암호화되지 않은 구역만 읽는다. 원소의 저주·어둠의 저주·불꽃 회오리 토템·요정의 불꽃(야성)은 여기서 찾지 못해 템플릿에서 뺐다.
- 게임 안에서도 `/매공 검사` 로 `GetSpellInfo` 가 nil 인 번호를 채팅에 알린다 (클라이언트 차이 대비).

- `/매공` 열기·닫기, `/매공 도움말`, `/매공 검사`, `/매공 초기화`, 별칭 `/매크로공방`, `/mk`, `/macrokit`
- 창 안: 템플릿마다 설명, 빈칸마다 툴팁, 첫 실행 안내 말풍선, 등록 결과 채팅 한 줄 ("'공포-마우스' 를 캐릭터 전용으로 만들었습니다. 창의 아이콘을 단축바로 끌어 놓으세요.")
- `.toc`: `Title`, `Notes`, `X-Usage-1..N` (애드온 도우미 [사용법] 창)
- 단축키: `Bindings.xml` 로 "매크로 공방 열기"

## 14. 정하지 않은 것

- 클래식 계열 클라이언트의 주시(`@focus`) 지원 여부 → 0단계 진단으로 결정
- 한글 슬래시 명령(`/시전`) 지원 여부 → 생성은 영어로 고정, 미리보기 설명만 한글
- 생명석 "있으면 사용, 없으면 만들기" 를 한 매크로로 만들 수 있는지 (`/use` 실패 시 다음 줄 진행 여부)
- 다른 직업 탭의 템플릿은 보기만 할지, 그 직업 캐릭터가 아니어도 등록은 막을지 (기본: 보기만, 등록은 내 직업만)
- `[stance:N]`/`[form:N]` 번호가 클래식 계열에서 요즘 와우와 같은지 (0단계 진단에 포함)
